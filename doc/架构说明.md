# AUV 固件架构说明

更新时间：2026-07-02

---

## 1. 总体结构

1. `Algorithm/`
   - 纯数值算法层，不依赖 RTOS 和硬件。
   - 包含 `KinematicProfile`、`PID_Controller`、`MathUtils`。
2. `Common/`
   - 全局上下文与线程安全共享状态。
   - 包含 `AppContext`、`MotionContext`、`SystemContext`、`LockedField`。
3. `Component/`
   - 高内聚业务组件。
   - 包含 `Chassis`、`MicroRos`、`Safety`、`RosLogger`、`ConfigService`、`HitlSimulator`。
4. `Peripherals/`
   - 外设驱动层。
   - 包含 `INS_Driver`、`MotionController_Driver`、`MS5837_Driver`、`USBL_Driver` 等。
5. `Porting/`
   - 硬件适配层。
   - 将 HAL/UART/I2C/DMA 细节封装成上层驱动可调用的 `PortOps` 接口。
6. `Application/`
   - FreeRTOS 任务层。
   - 包含 `ControlTask`、`MicroRosTask`、`MonitorTask`。

## 2. 任务模型

当前系统有三个独立任务：

### 2.1 `ControlTask`（100Hz）

文件：`UserApp/Application/ControlTask.cpp`

职责：
- 初始化 INS、深度计、底盘参数、日志系统。
- 更新导航状态：
  - HITL 模式读取 `HitlSimulator`
  - SITL 模式读取 `/zit6/sim/nav` 队列
  - 实物模式读取 `INS_Driver`，并按配置融合 MS5837 或 INS 压力深度
- 调用 `ctx_->chassis->update()` 计算 6-DOF 输出力/力矩。
- 如果已解锁，则通过 `MotionController_Driver` 下发推力；否则强制输出 0。

关键点：
- 固定周期运行：`vTaskDelayUntil(..., 10ms)`。
- `motion_context.last_dt_ms_` 当前由任务固定写成 10ms，而不是动态测量。
- 推力下发顺序为：
  - `publishThrust(fx, fy, fz, fyaw, fpitch, froll)`
  - 实际传入的是 `forces[0], forces[1], forces[2], forces[5], forces[4], forces[3]`

### 2.2 `MicroRosTask`（主循环 2ms）

文件：`UserApp/Application/MicroRosTask.cpp`

职责：
- 探测 micro-ROS Agent。
- 建立 / 断开节点连接。
- 初始化：
  - `MicroRosTransport`
  - `MicroRosSubscriber`
  - `MicroRosService`
  - `MicroRosPublisher`
- 周期性 `spin_some()` 执行订阅回调和服务回调。
- 调用 `publisher_.publish(now_ms)` 发布状态。
- 持续喂软件看门狗中的 `MICROROS` 通道。

关键点：
- `WAITING_AGENT` 状态下每 100ms 探测一次 Agent。
- 连接后每 2s 主动 ping 一次 Agent，掉线则清理并回到等待态。

### 2.3 `MonitorTask`（10Hz）

文件：`UserApp/Application/MonitorTask.cpp`

职责：
- 初始化软件看门狗。
- 调用 `SoftWatchdog::check()`。
- 只有全部受监控组件状态正常时才喂硬件看门狗 `IWDG`。
- 调用 `SafetyMonitor::check(HAL_GetTick())` 执行 ARM / DISARM 状态机。

这意味着安全逻辑已经从 `ControlTask` 中拆出，当前代码是三任务结构，不是两任务结构。

## 3. Common 层：全局上下文

### 3.1 `AppContext`

文件：`UserApp/Common/AppContext.hpp`

作用：依赖注入容器。所有任务都通过 `AppContext*` 访问驱动和组件，而不是直接依赖分散的全局变量。

当前注入对象：
- `INS_Driver* ins_driver`
- `MotionController_Driver* motor_driver`
- `MS5837_Driver* depth_sensor`
- `RosLogger* logger`
- `SoftWatchdog* watchdog`
- `ChassisManager* chassis`

### 3.2 `MotionContext`

文件：`UserApp/Common/MotionContext.hpp`

作用：跨任务共享的运动状态。

核心字段：
- `nav_state_`：当前导航状态，6-DOF 世界系位姿 + 6-DOF 机体系速度
- `current_setpoint_`：当前设定点
- `last_dt_ms_`：控制周期
- `last_received_seq_`：最后收到的 setpoint 序列号
- `last_output_forces_`：上次控制输出
- `home_offset_`：解锁时记录的原点偏移
- `sitl_nav_queue`：SITL 导航输入队列

### 3.3 `SystemContext`

文件：`UserApp/Common/SystemContext.hpp`

作用：系统级状态机上下文。

核心字段：
- `arm_state_`
  - `is_armed`
  - `heartbeat_count`
  - `last_heartbeat_ms`
  - `last_heartbeat_data`
  - `start_ms`
- `nav_status_`
  - `imu_state`
  - `dvl_state`
  - `lat/lon`
  - `timestamp`
- `is_planner_active`
- `planner_replan_flag`

`getNavigationValid()` 当前逻辑：
- `imu_state` 必须为 3 或 4
- 非 HITL 模式下，还要求 `INS_Driver::isDataFresh()` 为真

### 3.4 `LockedField<T>`

文件：`UserApp/Common/LockedField.hpp`

这是当前代码里最基础的并发保护手段。`get()` / `set()` 都使用 `taskENTER_CRITICAL()` 包裹，适合小结构体快照读写。

## 4. Algorithm 层：纯算法

### 4.1 `KinematicProfile`

文件：`UserApp/Algorithm/KinematicProfile.*`

作用：影子平滑器，为每个轴维护理想轨迹状态 `ProfileState{p,v,a}`。

当前接口：
- `updatePosition(target_p, dt)`
- `updateVelocity(target_v, dt)`
- `align(actual_p, actual_v)`
- `setLimits(max_v, max_a)`

当前实现特征：
- 已从旧版“4轴”扩展到控制器内部按 6 轴使用。
- 位置模式采用基于刹停距离的速度规划。
- 速度模式单独使用 `updateVelocity()`。
- 切层时通过 `align()` 实现无扰对齐。

### 4.2 `PID_Controller`

文件：`UserApp/Algorithm/PID_Controller.*`

作用：标准 PID 控制器。

当前特性：
- 比例 / 积分 / 微分
- 积分限幅
- 输出限幅
- 支持 `setIntegral()`，用于 Z 轴切层时继承推力配平
- 支持外部传入微分项

### 4.3 `MathUtils`

文件：`UserApp/Algorithm/MathUtils.hpp`

作用：6-DOF 数学工具，基于 Eigen 固定大小矩阵。

当前实现不是简单的二维 yaw 旋转，而是：
- `Vector6f`
- `Matrix6f`
- `eulerToRotationMatrix()`
- `eulerToRotationMatrixInverse()`
- `applyRotationToWorld()`
- `applyRotationToBody()`

这里的 6 轴索引约定为：
- `[0]=X`
- `[1]=Y`
- `[2]=Z`
- `[3]=ROLL`
- `[4]=PITCH`
- `[5]=YAW`

## 5. Component 层

### 5.1 Chassis：底盘控制

目录：`UserApp/Component/Chassis/`

当前底盘控制已经拆成三个类：

#### `SetpointRouter`

文件：`SetpointRouter.*`

职责：
- 解析来自上位机的 4-DOF 指令 `[X,Y,Z,Yaw]`
- 将其扩展为 6-DOF 目标
- 根据 `is_body` / `is_inc` 执行坐标变换与增量叠加
- 根据 `type_mask` 决定哪些轴不更新
- 在模式切换时对 `sp.pos_world` 或 `sp.vel_body` 进行对齐

注意：
- `type_mask` 语义是“bit 置 1 表示跳过该轴”，不是“bit 置 1 表示启用该轴”。
- 当前位置模式下，body 指令会先旋转到世界系。
- 速度/推力模式下，world 指令会先变换到机体系。

#### `CascadeController`

文件：`CascadeController.*`

职责：
- 真正执行数值控制。
- 持有：
  - `profiles_[6]`
  - `pos_pids_[6]`
  - `vel_pids_[6]`
- 输出 6-DOF 力/力矩矢量。

控制层级：
- `NONE`
- `POSITION`
- `VELOCITY`
- `ACTUATOR`

实现细节：
- 内部是 6 轴控制，不再是旧文档中的 4 轴控制器。
- Z 轴仍保留推力继承逻辑：`last_z_thrust_` / `last_output_forces_`。
- 注释明确写明：`update()` 按固定 `dt=0.01s` 演进，信任 `ControlTask` 的严格周期。

#### `ChassisManager`

文件：`ChassisManager.*`

职责：
- 整合 `SetpointRouter` 和 `CascadeController`
- 作为上层统一入口暴露给任务和服务层

当前对外接口：
- `applyConfig(cfg)`
- `getControlLevel()`
- `update()`
- `updateSetpoint(...)`
- `setControlLevel(...)`
- `configurePID(...)`
- `getPIDConfig(...)`
- `configureProfile(...)`

这意味着旧文档里“`ChassisManager` 集成了 Route + Cascade 的大部分职责”已经不成立，当前代码中二者是明确拆开的。

### 5.2 MicroRos

目录：`UserApp/Component/MicroRos/`

包含四个类：
- `MicroRosTransport`
- `MicroRosPublisher`
- `MicroRosSubscriber`
- `MicroRosService`

#### `MicroRosPublisher`

当前发布内容：
- `/zit6/state/pos`：约 30Hz
- `/zit6/state/vel`：约 50Hz（代码是每 20ms 一次，不是 62.5Hz）
- `/zit6/state/thr`：约 30Hz
- `/zit6/state/status`：10Hz
- `/zit6/state/zithbt`：1Hz
- `/zit6/log`：事件驱动

#### `MicroRosSubscriber`

当前订阅内容：
- `/zit6/cmd/setpoint`
- `/zit6/cmd/agxhbt`
- `/zit6/cmd/ins`
- `/zit6/cmd/servo`
- `/zit6/cmd/light`
- `/zit6/sim/nav`

当前实现要点：
- `onSetpoint()` 收到消息后先做 `isfinite` 检查。
- 未解锁状态下直接丢弃 setpoint。
- POSITION / VELOCITY 模式还要求导航有效，除非处于仿真模式。

#### `MicroRosService`

当前提供服务：
- `/zit6/update_params`
- `/zit6/get_params`

与旧文档不同点：
- `UpdateParams.srv` 不只有 `json`，还支持 `paths[] + values[]` 逐项更新。
- `GetParams.srv` 响应里除了 `config_json` 还有 `message`。

### 5.3 Safety

目录：`UserApp/Component/Safety/`

#### `SafetyMonitor`

文件：`SafetyMonitor.*`

职责：
- 已解锁时心跳超时检测
- 未解锁时解锁条件检查
- 解锁时记录 `home_offset`
- 上锁时清理 offset 并切回 `NONE`

当前阈值：
- 已解锁心跳超时：500ms
- 未解锁心跳计数清零：1000ms
- 最小解锁持续时间：1000ms
- 最小解锁心跳数：10 次
- `last_heartbeat_data == 3` 表示遥控模式，允许绕过导航检查

这与旧文档中的“200ms 超时 / 600ms 清零”不一致，必须以当前代码为准。

#### `SoftWatchdog`

监控组件：
- `MICROROS`
- `INS`
- `DEPTH`

### 5.4 `RosLogger`

作用：
- 线程间日志缓冲队列
- 由 `MicroRosPublisher` 转发到 `/zit6/log`

### 5.5 `ConfigService`

作用：
- 更新全局配置 `sys_config`
- 生成 JSON 返回给 `/zit6/get_params`
- 更新成功后由 `MicroRosService` 调用 `ctx_->chassis->applyConfig(...)` 热重载底盘参数

## 6. Peripherals 层

### 6.1 `INS_Driver`

文件：`UserApp/Peripherals/inc/INS_Driver.hpp`

当前能力：
- 通过 `InsPortOps` 抽象串口收发
- 解析 NAV-300 惯导字节流
- 输出 `NavState`
- 支持：
  - `setDvlPower(bool)`
  - `restart()`
  - `resetPosition()`
  - `setInitialPosition(lat, lon)`

### 6.2 `MotionController_Driver`

文件：`UserApp/Peripherals/inc/MotionController_Driver.hpp`

当前协议包：
- `ThrustPacket`
- `CurvePacket`
- `ServoPacket`
- `LightPacket`

当前固件发送的是 6 个 float：
- `Fx`
- `Fy`
- `Fz`
- `Fyaw`
- `Fpitch`
- `Froll`

因此旧文档中“`fpitch` / `froll` 一直为 0、不需要”已经不适合作为协议说明。上位机控制协议目前仍主要是 4-DOF，但控制板链路已经支持完整 6 通道载荷。

### 6.3 `MS5837_Driver`

支持两种后端：
- `UART_DepthBackend`（启用 `USE_DEPTH_CALC_BOARD` 时）
- `I2C_DepthBackend`（直连模式）

当前 `config.json` 默认启用了 `depth_calc_board.enabled = true`，因此实机默认走 UART 解算板路径。

### 6.4 `USBL_Driver`

当前代码中已经有 USBL 驱动实现，不应在文档中遗漏。

## 7. Porting 层

当前硬件绑定来自 `UserApp/Common/AppContext.cpp`：

- 深度解算板：`huart4`
- INS：`huart7`
- 动力控制板：`huart6`

对应 Porting 对象：
- `DepthCalcBoard_Porting`
- `INS_Porting`
- `MotionController_Porting`

其中 `MotionController_Porting` 当前关键点：
- DMA 发送前做 D-Cache Clean
- 使用 `.dma_buffer` 段内对齐的发送缓冲区
- 绑定串口是 `huart6`

## 8. 当前架构结论

当前真实代码可以总结为：

1. 三任务系统：`ControlTask + MicroRosTask + MonitorTask`
2. 六块核心结构：`Algorithm / Common / Component / Peripherals / Porting / Application`
3. 底盘控制已经拆为：`SetpointRouter + CascadeController + ChassisManager`
4. 控制器内部是 6-DOF 数值结构，虽然上位机主控制协议仍是 4-DOF
5. 安全逻辑已经独立成 `SafetyMonitor`
6. 配置系统支持运行时热更新
7. 已具备 SITL / HITL 两种仿真模式

如果后续继续维护文档，建议把本文件作为“当前实现说明”，而不是再混入未来设计设想。
