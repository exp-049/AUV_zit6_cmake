# 深度传感器与推杆驱动重构检阅

## 1. 结论

本次重构已完成，当前默认配置仍为自研 UART 解算板。

当前对象关系为：

```text
AppContext
 ├── depth_sensor    → Depth_Sensor_Driver
 │                    → Self_CalcBoard_Link
 │
 └── pushrod_driver  → Pushrod_Driver
                      → Self_CalcBoard_Link
                           → Self_CalcBoard_Porting
                                → UART4 DMA
```

深度和推杆共用同一个自研解算板协议后端及 UART4 DMA 接收器，避免两个模块分别启动 DMA 或重复消费接收数据。

模块目录已经收敛为：

```text
UserApp/Peripherals/
 ├── DepthSensor/  深度计 Driver/Backend
 ├── Pushrod/      推杆 Driver/Backend
 └── Presets/SelfCalcBoard/  自研解算板协议后端

UserApp/Porting/
 ├── DepthSensor/  深度计硬件适配
 ├── Pushrod/      推杆 GPIO 适配
 └── Presets/      硬件预设、UART4 DMA 和驱动总装配
```

其他外设也分别位于 `Peripherals/<Device>` 和 `Porting/<Device>`，每个目录独立维护自己的 CMake 文件。

选择 GPIO 推杆后，推杆链路独立为：

```text
AppContext
 ├── depth_sensor    → Depth_Sensor_Driver → selected depth backend
 └── pushrod_driver  → Pushrod_Driver
                      → Pushrod_GPIO_Backend
                           → Pushrod_GPIO_Porting
                                → PB8/PB7 motor bridge
```

## 2. 后端选择

统一硬件预设入口：

```text
UserApp/Porting/Presets/inc/Hardware_Preset.h
```

支持的预设：

| 值 | 预设 | 深度 | 推杆 |
|---|---|---:|---:|
| `1` | 自研解算板 | 自研 UART | 自研 UART |
| `2` | 自研深度 + GPIO 推杆 | 自研 UART | PB8/PB7 GPIO |
| `3` | 商品解算版 | 商品 UART | 不支持 |
| `4` | M14 深度计 | M14 UART | 不支持 |
| `5` | I2C 深度计 | MS5837 I2C | 不支持 |
| `6` | 商品深度 + GPIO 推杆 | 商品 UART | PB8/PB7 GPIO |
| `7` | M14 深度 + GPIO 推杆 | M14 UART | PB8/PB7 GPIO |

默认值为 `1`。

通过 CMake 只选择一个完整预设：

```text
-DAUV_HARDWARE_PRESET=1  # 自研解算板
-DAUV_HARDWARE_PRESET=2  # 自研深度 + GPIO 推杆
-DAUV_HARDWARE_PRESET=3  # 商品解算版
-DAUV_HARDWARE_PRESET=4  # M14
-DAUV_HARDWARE_PRESET=5  # I2C MS5837
-DAUV_HARDWARE_PRESET=6  # 商品深度 + GPIO 推杆
-DAUV_HARDWARE_PRESET=7  # M14 深度 + GPIO 推杆
```

GPIO 后端的固定映射为：

| `speed` / `power_x1000` | PB8/IN1 | PB7/IN2 | 行为 |
|---|---:|---:|---|
| 大于 0 | 1 | 0 | 正向 |
| 小于 0 | 0 | 1 | 反向 |
| 等于 0 | 0 | 0 | 安全停止 |

该后端忽略速度绝对值，不创建 PWM、定时器或 DMA；`duration_ms` 仍由后端轮询计时，到期后输出 `00`，随后才产生任务 ACK，避免上层队列在电机仍运行时启动下一条任务。ROS 话题仍为 `/zit6/cmd/pushrod`，上层消息格式不变。

由于当前硬件 PB7/PB8 同时是 I2C1 的 SDA/SCL，当前没有提供 I2C + GPIO
预设。GPIO 预设下启动流程不调用 `MX_I2C1_Init()`。

## 3. 接口变化

### 深度

应用层使用 `Depth_Sensor_Driver`，接口保持原有调用习惯：

```cpp
Init();
start();
Read();
getMS5837Z();
Depth();
```

`MS5837_Driver.hpp` 保留为兼容头文件，并将旧名称别名到 `Depth_Sensor_Driver`。

深度诊断统一通过 `DepthDiagnostics` 获取，UART 专有字段对 I2C 和不提供该能力的后端返回默认值。

### 推杆

推杆不再属于深度驱动，应用层改为使用：

```cpp
Pushrod_Driver::sendTask();
Pushrod_Driver::readAck();
Pushrod_Driver::poll(now_ms);
Pushrod_Driver::stop();
```

商品解算版、M14 和 I2C 后端通过不支持 Backend 安全返回失败，不会执行任何硬件发送。
M14 后端同样不支持推杆；它使用 `T=XX.XXD=XX.XX\r\n` 数据帧，并在
`M14_UART_Backend` 内部实现 `!D`、`!T`、`!F`、`!!`、`!R`、`!r`、`!C`
命令。

## 4. 自研 UART 链路

`Self_CalcBoard_Porting` 是 UART4 DMA 的唯一拥有者，负责：

- 启动 `HAL_UARTEx_ReceiveToIdle_DMA()`；
- 轮询 DMA 环形缓冲；
- 向 `Self_CalcBoard_Link` 喂入协议字节；
- 转发 UART 错误、恢复次数和 DMA 位置诊断。

`Self_CalcBoard_Link` 同时实现 `DepthBackend` 和 `PushrodBackend`：

- `DATA` 帧更新深度和温度；
- `HANDSHAKE_ACK` 帧更新链路状态；
- `PUSHROD_ACK` 帧进入推杆 ACK 队列；
- 推杆任务沿同一 UART4 发送。

推杆初始化和启动不应再次调用共享链路的生命周期。当前由 `Depth_Sensor_Driver::Init()` 和 `start()` 启动共享链路，`Pushrod_Driver` 只执行推杆发送和 ACK 读取。

## 5. 代码变更概览

- 新增 `Depth_Sensor_Driver`、`Pushrod_Driver`、`PushrodBackend`。
- 新增 `M14_UART_Backend`，直接集成 M14 的 ASCII 数据和命令协议。
- 新增 `Self_CalcBoard_Porting` 和硬件预设组装入口
  `Porting/Presets/src/Peripheral_Preset.cpp`。
- 将深度计和推杆分别放入 `Peripherals/DepthSensor`、
  `Peripherals/Pushrod`、`Porting/DepthSensor` 和 `Porting/Pushrod`，由模块级
  CMake 管理。
- 将同时实现深度/推杆协议的 `UART_MS5837Backend` 放入
  `Peripherals/Presets/SelfCalcBoard`，由自研解算板预设使用。
- 新增 `Pushrod_GPIO_Backend`、`Pushrod_GPIO_Porting` 和统一的
  `AUV_HARDWARE_PRESET` 编译期选择。
- 现有 `UART_MS5837Backend` 扩展为共享的深度/推杆链路后端。
- `AppContext` 增加 `pushrod_driver`，应用层不再从深度驱动发送推杆。
- `ControlTask` 不再根据 `USE_DEPTH_CALC_BOARD` 分支选择深度流程。
- `MicroRosSubscriber` 通过 `Pushrod_Driver` 处理任务发送和 ACK 重试。
- 保留 `MS5837_Driver` 兼容别名。

## 6. 验证结果

### 主机测试

```text
102 个测试通过
1 个已有测试被显式 Disabled
0 个失败
```

新增覆盖：

- 深度 Driver 生命周期和深度回调缓存；
- 深度后端初始化失败状态；
- 推杆任务发送和 ACK 读取；
- 不支持推杆后端的安全失败行为。
- GPIO 推杆正转、反转、零速安全停止、定时停止和强制停止。

### 固件编译

以下有效配置完成 ARM 固件编译和链接：

```text
AUV_HARDWARE_PRESET=1  自研解算板                         通过
AUV_HARDWARE_PRESET=2  自研深度 + GPIO 推杆               通过
AUV_HARDWARE_PRESET=3  商品解算版                         通过
AUV_HARDWARE_PRESET=4  M14 深度计                        通过
AUV_HARDWARE_PRESET=5  I2C MS5837                        通过
AUV_HARDWARE_PRESET=6  商品深度 + GPIO 推杆               通过
AUV_HARDWARE_PRESET=7  M14 深度 + GPIO 推杆               通过
```

默认自研 UART 配置的链接结果保持在芯片资源范围内：

- FLASH 约 375 KB / 2 MB；
- RAM 约 260 KB / 512 KB；
- RAM_D2 约 5.5 KB / 288 KB。

## 7. 尚未完成的硬件检验

本次验证没有连接实际解算板，因此以下项目仍需上电后确认：

- UART4 实际只启动一次 DMA；
- 深度 DATA 和推杆 ACK 同时到达时不丢帧；
- UART 错误恢复后协议解析可以继续工作；
- 自研解算板对推杆任务的 ACK、队列满和重发行为符合协议；
- 商品解算版实际文本格式与现有解析器完全一致。
- M14 实际数据帧、配置命令和 UART 电平/波特率与传感器手册一致。
- GPIO 电机桥的 IN1/IN2 电平极性、PB8/PB7 复用关系和电机电源隔离符合实物接线。
- GPIO 后端不能调速；`speed` 的绝对值只用于判断方向，不代表 PWM 占空比。
